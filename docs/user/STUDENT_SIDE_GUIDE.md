# AccessFlow Student Side Guide

This guide explains how the student/client side of AccessFlow is intended to work.

AccessFlow is a prototype visual schedule and communication-support tool. It is designed to help a student/client understand what is happening, add appropriate choices to their schedule, communicate needs, ask for help, calm down, and use simple play activities.

> **Prototype safety note:** AccessFlow is not HIPAA certified and not FERPA certified. Use fake/demo data only.

## Student Mode purpose

Student Mode should answer five basic questions:

```txt
What am I doing?
What can I add?
What can I say?
How do I ask for help?
How do I calm or play?
```

The default student layout is:

```txt
Schedule | Add | Talk
Help     | Calm | Play
```

Some profiles may show fewer or more tabs depending on staff settings.

## Main student tabs

### Schedule

Use **Schedule** to see the day’s activities.

The Schedule screen usually includes:

- **Now / Next**: what is happening now and what comes next.
- **Add to schedule**: quick approved activities the student can add.
- **Schedule list**: activities in order.
- **Activity steps**: smaller steps inside an activity.

Common student actions:

1. Look at **Now / Next**.
2. Tap an activity to open its steps.
3. Tap steps as they are completed.
4. Use **Add to schedule** to add an approved activity.
5. Use Help or Calm if something is hard.

### Add

Use **Add** to add approved activities to the schedule.

This is the student independence path:

```txt
Pick a card -> Add it to my schedule -> See it on Schedule
```

The Add tab shows activities that staff created in Staff Mode. These are meant to be safe, approved choices.

If no choices appear, staff needs to add schedule choices first.

### Talk

Use **Talk** for communication.

Talk can include:

- Choice board buttons.
- AAC-style core words.
- Quick phrases.
- Feelings and intensity choices.
- Yes / No / Maybe.
- Social scripts.
- Community and vocational cards, if enabled.

Talk is for communication. It is not the main place for building the schedule.

### Help

Use **Help** when the student needs support.

Help can include:

- I need help.
- I need a break.
- I am stuck.
- I want to change the schedule.
- I need help making a choice.
- Transition support.

Help should stay easy to find because students may need it when they are stressed.

### Calm

Use **Calm** for regulation, sensory supports, waiting, and recovery.

Calm can include:

- Break supports.
- Sensory requests.
- Regulation pathway.
- Waiting support.
- Calm screen.
- Communication repair tools.
- Switch-scanning prototype tools.

Calm is for reducing stress, not for adding schedule activities.

### Play

Use **Play** for simple games.

Current games include:

```txt
Rock Paper Scissors
Choice Wheel
Word Rescue
Tic Tac Toe
Snake
Dino Jump
Memory Match
Float Bird
```

Play can be used as a break, reward, regulation support, or simple recreational activity.

## How to add a student choice to the schedule

The clearest path is:

1. Open **Student Mode**.
2. Go to **Schedule**.
3. Find **Add to schedule**.
4. Tap an activity card.
5. Confirm the activity appears in the schedule list.

The second path is:

1. Open **Add**.
2. Pick an approved activity card.
3. Tap it to add it to the schedule.
4. Return to **Schedule**.

## What if no choices appear?

If the student sees no choices, staff needs to create them.

Staff should go to:

```txt
Staff Mode -> Choices -> Student schedule choices
```

Then create approved activities the student can add.

## What if Play is missing?

Staff can enable it:

```txt
Staff Mode -> Students -> Student display and access settings -> Enable Play tab
```

The default Core layout should show Play.

## Student navigation presets

Staff can choose different student layouts.

### Core

```txt
Schedule | Add | Talk | Help | Calm | Play
```

Best default for most students.

### Simple

```txt
Schedule | Help | Calm
```

Best for very low-clutter access.

### Communication

```txt
Talk | Help | Calm | Schedule
```

Best when communication is the main goal.

### Builder

```txt
Schedule | Add | Make | Help
```

Best when the student is practicing planning and schedule-building.

### Full

```txt
Me | Schedule | Add | Make | Talk | Help | Calm | Play
```

Best only for students who can handle more navigation choices.

## Access and visual supports

Student Mode supports:

- Large touch targets.
- Emoji icons.
- Font Awesome icons.
- Uploaded image visuals.
- Text labels.
- Text-to-speech/read-aloud behavior.
- Reduced-choice and eye-gaze-friendly settings.
- Visual preference modes.

Labels should remain visible unless a staff setting intentionally changes the display mode.

## Recommended student workflow

For a typical session:

1. Start in **Schedule**.
2. Review **Now / Next**.
3. Add one choice if appropriate.
4. Complete activities and steps.
5. Use **Talk** to communicate.
6. Use **Help** if stuck.
7. Use **Calm** for regulation.
8. Use **Play** as a reward, break, or calm activity.

## Design principle

Student Mode should support independence.

The student should not need to remember hidden staff logic. Important actions should be visible, plain-language, and connected to the student’s goal:

```txt
I choose -> I add -> I do -> I communicate -> I get support
```


## Staff sharing note

Students do not need separate staff accounts. Staff accounts manage the shared student list from Staff Mode.
